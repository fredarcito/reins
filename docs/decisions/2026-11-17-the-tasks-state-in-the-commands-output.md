# The task's state in the commands' output (2026-11-17)

Feedback from a real session (DEV-8914, repvue-employer): reins reached a branch half-way through a task (31 files, 2 domains, a staging merge). The next session never triaged, treated each request as a small fix, never proposed closing, and missed a new feature folder that no domain covered. The principle: an agent reliably follows the output of the command it just ran; rules in AGENTS.md lose to the task in long, iterative conversations.

| Topic | Decision | Why |
| --- | --- | --- |
| resume measures | Without a notebook and with no triage line on the branch, resume measures the changed files (`scopeSignals` + `suggestLevel`, doctor.yml thresholds) and prints the level with the command to run; medium/large add the notebook step. A medium or large open task without a notebook is told to create one; a closed one, that a new request needs triage. Nothing for an open small task | It said "fine for a small task" without measuring, which pointed the agent the wrong way |
| Closed is a state | `progress close` appends `\| status:closed` to triage.log (level, commit and task copied from the task's lines), with or without a notebook; without one it runs the same note checks and refuses when no task was measured | Without a notebook "No notebook" left no trace, so open and closed were not states reins could read. Copying the commit keeps the doctor's per-task diff unchanged |
| Ready to close | `doctor` (clean) and `check` (passing, outside CI, without `--files`) end with one line proposing the close for an open medium or large task; the done skill names indirect signals ("it works", "listo", "lo probé", "thanks") and that line | The moment to propose closing is when nothing is left to flag; the skill alone was never triggered |
| `domain-uncovered` | Doctor rule and a `scope` warning: a folder the task put code in that no domain covers (no file of it in a domain), while at least 2 and 3 of 4 of its sibling folders are each fully a domain. Names the notes that mention it (`parent/name` or `` `name` ``) | The PR map already groups domain-less files, but in a layer with domains every shared folder is domain-less too; requiring domain siblings reports a missing feature folder and stays silent on shared code |
| Only with changes (2026-11-17) | "Ready to close" and resume's open-task line need a counted change in the task's diff. A line without a commit (reins before 0.9) written before a task that landed is stale too | Found right after closing: the closed tasks landed, their lines went stale, and a commit-less line from 2026-11-08 resurfaced as an open medium task with nothing to close |
| Not done | "task open (level)" on every command (repeats resume and Ready to close; noise is what made rules get ignored). A level-up warning in `check` or the edit hook: `triage` and `progress` edits already warn, and a diff per edit is too slow; backlog A9 until a task grows unnoticed. A note-mentions-uncovered-path rule in general: notes name other modules' folders all the time; only the domain-less case is reported |  |

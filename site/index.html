Hold the reins of your coding agents.

Agents write code fast, then forget. They violate your architecture one import at a time, and re-read your codebase from scratch every session. reins makes both problems a check.

  • ✓Architecture becomes a check — runs on every commit and PR, whatever agent wrote the code. When something breaks a rule, the commit is blocked with the reason and the fix, so the agent corrects it before you even review.
  • ✓Each module gets a short note — what it does, how it works, its decisions and traps. It reaches the agent when it opens a file of that module, and the task's notebook comes back on its own after a compaction.

01 · The difference

Without reins, the review is the safety net. With reins, the check is.

Every row is a failure mode of agent-driven development — and what changes when the rules leave the prompt and live in a tool.

Without reins
  • ✕A shared component imports from a feature. Someone spots it in review — or nobody does.
  • ✕A week later, the agent reads a whole module again to find out what it does and why.
  • ✕A long conversation gets compacted and the task's decisions are lost.
  • ✕Architecture rules live in a long prompt the agent skims.
  • ✕"Review the whole project" every few weeks, from scratch.
  • ✕Adopting rules means fixing all the old debt first.
With reins
  • ✓The commit is blocked; the agent reads the fix and corrects it.
  • ✓Its note — purpose, map, decisions with their why, traps — reaches the agent as soon as it opens the module.
  • ✓The notebook and the notes of the files in play come back right after the compaction.
  • ✓They live in architecture.yml, checked by a tool. The prompt stays at 30 lines.
  • ✓Findings stay in a backlog; the next audit rechecks them.
  • ✓Old debt is frozen in a baseline and can only shrink.

02 · The check

The core never opens your files. It checks the edges.

A language adapter turns the repo into a list of import edges; the core applies the rules declared in architecture.yml to that list. Deterministic, identical locally and in CI, whatever agent or model wrote the code.

04 · The core idea

Everything falls on one side of a line: enforced or instructed.

What a machine refuses to let through, and what it hands the agent as guidance. Both matter; only one of them can't be ignored.

Enforced by a machine
  • ▸reins check in the git hook and CI
  • ▸baseline.json — existing violations frozen
  • ▸Integrity of architecture.yml, baseline.json and generated files
  • ▸Branch protection: PR with human approval + CI green
  • ▸Claude Code permissions denying git commit / push (a first line of defense)
Guidance for the agent
  • ▸Announcing the task level (triage)
  • ▸Progress notebook
  • ▸Module notes, policies, skills, agents
  • ▸Audit backlog
  • ▸Multi-agent rules

06 · Status

Stable core, honest edges.

The enforcement core is stable. Agent-assisted workflows are documented as experimental — verify current behavior in the repository before relying on it in production CI.

Stable

  • reins check
  • reins init
  • adapter-js
  • next-server-client (optional)
  • git hook + CI

The deterministic core: rules, findings, baseline.

Experimental

  • reins install
  • reins sync
  • notes management
  • reins doctor
  • audit / progress / review
  • skill templates

reins doctor sits in the middle: it warns locally about agent-written artifacts but never blocks and never runs in CI. Current status: docs/STATUS.md ↗

07 · Quick start

Green on the first commit, from the root of your project.

Node 22 or newer. Four commands, and only new violations can fail.

01
npm install -D @agentreins/cli @agentreins/adapter-js

Add the CLI and the JS/TS language adapter as dev dependencies (pnpm: pnpm add -D).

02
npx reins install

Sets up the git hook, the CI job, AGENTS.md and .claude/. Additive and idempotent: it never overwrites your files, and never installs packages.

03
npx reins init

Drafts the architecture plan, the baseline and the module notes. Review them: in Claude Code type /reins-arch (the agent proposes changes with evidence, you approve each one); otherwise read .reins/init-report.md and edit .reins/architecture.yml yourself. Then /reins-notes — or ask your agent to fill in the notes' TODO lines.

04
npx reins check --update-baseline

Freezes today's violations. From now on, npx reins check fails only on new ones. Commit everything and make the "reins" job required in branch protection.

Updating later: bump both packages, then run npx reins sync, npx reins doctor, npx reins check and npx reins notes stale to review out-of-date notes. Nothing is overwritten: install and init only add files or ask first.

# cli

## Purpose
The `reins` command line: wires the provider-neutral core and language adapter to a consumer repo's files and git, with an optional Claude Code adapter (`check`, `init`, `doctor`, `sync`, `notes`, `scope`, `impact`, `resume`, `audit`, `progress`, `review`, `install`, `update`).

## Map
- Files: 33. Used by: nothing outside the module. Depends on: domain core (13), only through `@agentreins/core`; adapters are loaded at runtime, never imported
- `src/main.js`: `run(argv, io)` — command table, `parseArgs`, repo root, `CliError` -> exit code. Everything in `io` is injectable for tests.
- `src/context.js`: `.reins/` file paths, repo root, package-manager commands, `CliError`. `src/templates.js`: finds `templates/` (packed copy or monorepo root). `notes-seen.js`, `notes-draft.js`: notes hook state and drafting. `local-state.js`: `writeFileAtomic` and `withFileLock` for local state files several processes write.
- `src/project.js`: reads `architecture.yml` domains, `doctor.yml` and notes without loading the adapter; `listRepoFiles` (git ls-files, or a walk without git), `readHistory` and `dirtyFiles` for doctor's `note-dead-*` and `notes stale`; `changedFiles` (since a commit or the merge base); `liveBranches` (local + remote-tracking refs + the current branch).
- `src/notebooks.js`: one notebook per task. 2026-11-10: `progress show` only reads; commands that edit claim the task (reading another session's task used to take it). `resolveTask` (shared by `progress`, `resume`, `triage`: explicit `--task`/`REINS_TASK` → the open task whose `session:` is this session → no session id and one open → the older `<branch>.md` while open → none), `sessionId` (hook payload, `CLAUDE_CODE_SESSION_ID`, `REINS_SESSION`), `cleanNotebooks` (run by `resume`). `project.js` `listNotebooks` finds them.
- `src/impact-map.js`: `impactMap` (importers count + level per imported file, one pass), `buildImpactMapInBackground` (resume --hook), `impactHint` (used by the notes hook: speaks only when the declared level is below impact's minimum, or untriaged).
- `src/pr-map.js`: `review --map`: `buildPrMap` (merge base, head adapter reused for the base graph, changed files with `--name-status -M`, head and base graphs, new violations, `impactOf` per changed file, then core's `prStructure` + `renderPrMap`; with several adapters it passes `zones` from `analyze()`'s `byAdapter`, head and base files), `withCheckout` (a temporary git worktree under the gitignored .reins/tmp folder, always removed), `parseNameStatus` (git -z, so names are never quoted); each process uses its own worktree folder and removes the ones of dead processes.
- `src/commands/triage.js` (2026-11-10) takes `--files` and measures the level (`scopeSignals` + `suggestLevel`, like `scope`; `expand` is shared from `scope.js`), recording the higher of declared and measured (the level is optional: the agent names files, reins states the level; loose words after a quoted reason are more files, because `--files a b c` gives `b c` as positionals and measuring only `a` under-reports; below `large` the files are required; `--override` = the person's `[quick]`/`[deep]`, not measured); 2026-11-12: without files and without a level it only suggests (`suggest`: core's `suggestNotes` over the notes and the repo folders, test/fixture folders left out; prints the two best notes, records nothing); with files it prints their notes (`notesOf`). Both share the hook's once-per-session record (`takeUnseen`). `commands/doctor.js` `levelDrift` (never throws) gives `triage` and every `progress` edit the `triage-mismatch` warning mid-task. Notes go before the `Recorded in …` line, which stays last. `src/triage-log.js`: `readTriage` (triage.log without stale lines), `cleanTriageLog` (run by `resume`), `taskFiles` (the current task's diff since the commit on its latest line, or the branch diff). Used by `doctor`, `resume` and `triage`.
- `src/adapter.js`: resolves `@agentreins/adapter-<x>` / `reins-adapter-<x>` from the repo root, checks `reins.contract`, validates it. `guessAdapterNames` (for `init`): Rails markers → `rails`, then `package.json` → `js`; `init` requires the first and adds the others only when installed and `detect` is true.
- `src/commands/check.js` `analyze()`: the one place that loads adapters (`adapter:` or `adapters: [...]`) and builds the graph; `check`, `impact`, `notes new`, `init` and the PR map all go through it. Returns `{ config, loaded: [{ adapter, packageName }], graph, extra }`; `knownRulesOf(loaded)` refuses rule ids two adapters share. 2026-11-09: each adapter's `evaluate` gets only its own graph, and `preset` only reaches the adapter that lists it (adapter-js throws on unknown presets; `checkPreset` refuses a preset no adapter lists, else a typo is dropped silently); `init` drafts for every adapter since 2026-11-10 (one preset each, joined); `sync` migrates `adapter: js` (`migrateAdapterKey`, the only edit it makes to the plan; see `docs/DECISIONS.md`).
- `src/base.js` (2026-11-11): what every command compares with. `baseBranch` (`--base` → `REINS_BASE` → `origin/$GITHUB_BASE_REF` → `base:` → `origin/HEAD`…; a missing `REINS_BASE`/`base:` always warns), `branchStart` (the reflog's `branch: Created from`, the parent from HEAD's `checkout: moving from`), `comparison` (`--base` → triage anchor → branch start, moved up to the newest merge base with its parent → base branch; returns `commit`, `ref`, `label`, `mark`, `warnings`), `suggestBase` for `init`/`sync`. `taskFiles` (`triage-log.js`), `check`, `review`, `pr-map.js`, `doctor`, `resume` all go through it; `check`/`review`/map never pass the triage anchor. Trap: the branch start is skipped in CI (`CI` or `GITHUB_BASE_REF` set), where a checkout's reflog could empty the diff and hide an integrity finding; tests pass `env: {}`.
- `src/commands/*.js`: one file per command exporting `options`, `help` and the run function.
- `src/sync/index.js`: syncs packaged defaults from `templates/.reins/core/` into the consumer's core source directory and updates the shared rules/notes blocks in AGENTS.md; the Claude Code adapter is optional (`--skip-claude`); its preference is persisted in `.reins/.generated.json`.
- `src/commands/update.js`: upgrades the CLI and installed adapters with the project's package manager, then runs the newly installed `reins sync` executable.
- `src/init/`: `infer.js` (layers, domains, rules from the graph and preset), `render.js` (YAML and init report), `conventions.js` (2026-11-10: what is source, a test, an index file, which kinds to ignore, how route folders are named (`routes`) and where the code lives (`folderOf`), built from the adapters' presets; `infer.js` and `coverage.js` know no language and take it as `lang`. Never add an extension or a file name to the CLI: add a preset field. `presetsOf` picks each adapter's preset; `mergePresets` in `commands/init.js` joins them for a draft with several adapters; see `docs/DECISIONS.md`).
- `init` domains: `domains_from` first; only if it finds none, `route_domains_from` (one domain per route folder; `[param]` and `(group)` looked through; fewer than 2 source files and no owned folder → left out, listed in the report; 2026-11-09: every route folder competes in `inferOwnedFolders` first, because a repo with thin `routes/x/index.jsx` and the code in `components/pages/x` lost all its modules (repvue-employer: 3 domains of 26 routes); then `mergeSmallRoutes` joins the small routes that share a feature folder only they use into one domain. Route domains then take feature folders by imports (`inferOwnedFolders`: never by names, through barrels via the adapter's `uses`; whole folders at 2/3 of imports inside folders organized by feature, 100% right under a layer root; never the lowest layer or a shared container) and, in their notes only, the loose files only they use (`loose`). A domain's note is skipped only when a note named after it exists, or a top-level note whose paths all lie inside it (then its parts go in that note's folder); a broader note never blocks it. Notes are drafted per domain, so no domains means no notes. Route domains also get one note per part (`inferSubmodules`: looks through `(group)`/`[param]` and single-folder chains, 2+ source files, max 12), named `<domain>/<part>` and written to `.reins/notes/<domain>/<part>.md`; parts are notes, never domains. `loadNotes` reads note folders; `sync` puts parts on their module's line in the AGENTS.md index; `notes new <folder inside a domain>` drafts a part.

## How it works
`bin.js` calls `run`, which picks the command and passes a context (`root`, `cwd`, `values`, `out`, `err`, `env`, `confirm`, `today`). Commands do the I/O (files, git) and call pure core functions. `check` loads the config, resolves the adapter, builds the graph, adds integrity (git merge base) and generated-file divergences (`sync --check`), then runs `runCheck` and prints the report. `update` runs `sync` through the package manager after dependency updates so it uses the newly installed CLI rather than the already-loaded process. Exit codes: 0 ok, 1 new errors, 2 could not run.

## Decisions
- 2026-11-04: no CLI framework, `node:util` `parseArgs`. The npm scope is derived from the package's own name (`scope.js`), never hardcoded. The CLI never installs packages; a missing adapter prints the install command for the repo's package manager.
- 2026-11-04: `sync` only touches what its manifest records; third-party skills, agents and settings are never overwritten or deleted. Hand-edited generated files are overwritten with a message. 2026-11-13: generated files git ignores (`ignoredPaths`, `git check-ignore`; repvue-employer ignores `.claude/`) never become `divergences`: `sync` returns them as `ignored`, and `check` turns those into one plain warning outside CI. `sync --local` writes only them (`mine(rel)` guards every record and write; never the manifest); `sync` adds `(reins sync --local || exit 0)` to package.json's `prepare` (`postinstall` with yarn, `installScript`) only when something generated is ignored. See `docs/DECISIONS.md`.
- 2026-11-04: Claude Code hooks (`notes --hook`, `resume --hook`) must never fail: any error means no output and exit 0.
- 2026-11-04: on `compact`/`clear`, `resume --hook` forgets the session's seen-notes record so notes are delivered again.
- 2026-11-05: `sync` never writes an AGENTS.md that doctor rejects: the notes index fits in `agents_md.max_lines` minus the hand-written lines, or shrinks to its first line (`fitNotesIndex`). That line always says to run `reins notes <path…>`: the hook misses shell reads and MCP tools. 2026-11-12: notes come before exploring: `triage "<reason>"` suggests them, the AGENTS.md index ends each line with the note's Purpose (`notePurpose`), the hook also matches `Grep|Glob` (a folder → the notes of a file inside it; the repo root → none) and says "start from them; the code wins if they disagree, and say so". No hook on Bash (cost on every command). See `docs/DECISIONS.md`.
- 2026-11-06: `impact` passes the adapter's `uses` to `impactOf` so importers behind a barrel count as consumers; without it a re-exported util shows only the barrel and the level comes out too low.
- 2026-11-07: packaged policy, skill, agent, and notebook defaults live in `templates/.reins/core/` and sync copies them into the consumer's `.reins/core/`; `.reins/{skills,agents,policies,templates,review}/` are overrides.
- 2026-11-07: upgrading from <= 0.7.4: `sync` removes unmodified copies of shipped defaults from those override folders (frozen sha256 list in `src/sync/legacy-defaults.json`, plus the current core) and moves an unedited legacy `## Always`…`## On demand` section into the rules block. Anything edited is kept; edited rules only get a warning. Without this every old repo would freeze on its copied skills and get the rules twice.
- 2026-11-07: shared workflows use plain Markdown in `AGENTS.md` and the reins CLI; `sync`, `install`, and `update` accept `--skip-claude` to avoid touching provider-specific files. Client-level instruction loading outside Claude Code is unverified.
- 2026-11-07: `sync` persists whether the optional Claude Code adapter is enabled in its generated manifest so bare `sync --check` and CI use the same choice; `--claude` explicitly re-enables it.
- 2026-11-07: `sync` writes a README into `.reins/{skills,agents,policies,review}/`; `templates/` gets none on purpose (the notebook format is parsed by `progress`, `resume` and doctor, so overriding it is not advertised, and the policies README asks not to shadow reins' policies): without it, after the migration removes the old copies nobody knows where their own skills go. `install` skips those folders; agent scanning skips `README.md`.
- 2026-11-08: when `sync` overwrites a hand-edited file it never points to `templates/…` (inside the package) or `.reins/core/` (rewritten too): `editHint` names the override folder (skills, agents, review) or says reins rewrites it.
- 2026-11-08: `update` reads the installed CLI version before and after the package manager and says `X -> Y` or "still X" (`versionReport`), because package managers exit 0 when they hold `@latest` back.
- 2026-11-08: each task is anchored to its start commit (`reins triage` writes `commit:<HEAD>`); doctor and resume use the task's diff. A line is stale when its branch is gone or its task has landed (commits since its commit, all already in the base): not "its commit is in the base", which is true for every task started on main or right after branching. See `docs/DECISIONS.md`.
- 2026-11-08: notebooks are per task (`<branch>/<task>/notebook.md`), see `docs/DECISIONS.md`. Every `progress` command, `show` included, claims the task it acts on (`session:`), so a compaction finds it again. A new session never gets a task silently; the exceptions (no session id with one open task, the older `<branch>.md`) are flagged `guessed` and resume says so.
- 2026-11-08: Cursor runs the hooks in `.claude/settings.json` (VERIFIED P12), so there is no Cursor adapter; `sync` only adds a no-op `sessionStart` to `.cursor/hooks.json` (`CURSOR_HOOKS`, `mergeCursorHooks`, owned entries in the manifest's `cursor`), because Cursor requests session start only when a native hook defines it. Calling reins there would run resume twice. Hook responses always use Claude's event names (`hookEventName` in `context.js`; Cursor sends `preToolUse`/`sessionStart`), and `sessionId` also reads `CURSOR_CONVERSATION_ID`. Cursor sends no `source` on session start, so it never resets the seen notes.
- 2026-11-08: the notes hook carries the impact warning, from a map built detached at session start (graph per edit is too slow). Its once-per-session record reuses `.notes-seen.json` with `impact:` keys, so a compaction resets it too.
- 2026-11-08: `.notes-seen.json` is updated under `withFileLock` and replaced with `writeFileAtomic`: parallel tool calls run their hooks at the same time, and plain read-modify-write delivered a note twice and left invalid JSON (which reads as empty, so every session got its notes again). The lock gives up after 200 ms and runs anyway (hooks never block or fail); a lock older than 5 s is stale.
- 2026-11-08: `review --map` builds the base graph in a git worktree and calls the adapter's optional `prepareCheckout` first (a bare worktree reports every pnpm workspace import as new; VERIFIED P14). Exit 0 even with violations, 2 when it could not run.
- 2026-11-09: `progress close` refuses until the done steps are met: every item done or dropped, and no module note of the task flagged by the doctor (`doctorResult` in `commands/doctor.js`, shared). `--notes-ok "<why>"` overrides only the notes and records the reason as the Next step. An agent had closed a task without updating notes. See `docs/DECISIONS.md`.

## Traps
- Commands read the session from `ctx.env`, never `process.env`: tests run inside Claude Code sessions that set `CLAUDE_CODE_SESSION_ID`.
- `cleanNotebooks` deletes files: it only runs inside `resume`, after `liveBranches`; an open task of a live branch is never removed.
- pnpm 11 has `minimumReleaseAge` (a day by default): `pnpm add pkg@latest` resolves to the newest release old enough and says "Already up to date". An exact version installs and adds a `minimumReleaseAgeExclude` entry. Don't bypass it from `update`.
- `update` at a pnpm workspace root must pass `-w` to `pnpm add`, or pnpm refuses to install.
- `legacy-defaults.json` is frozen history: never add new core versions to it; the current core is compared at runtime.
- `cwd` and root are real paths on purpose: macOS `/var` -> `/private/var` would break `--files` repo-relative paths.
- Adapter resolution starts at the consumer repo, not the CLI folder: with pnpm the CLI can't see packages it doesn't declare.
- `confirm` is undefined without a TTY (CI, hooks, agents): commands that would overwrite must refuse and suggest `--force`/`--dry-run`.
- Report goes to stdout (pass or fail); usage and setup errors to stderr.
- `review --map` leaves nothing behind: the worktree is removed in `finally` and on SIGINT/SIGTERM, and a leftover from a killed run is removed first. The .reins/tmp folder is gitignored here; consumer repos see an untracked folder only while it runs.
- `templates/` lives at the repo root and is copied into the package only at pack time.
